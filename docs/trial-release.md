# إرسال نسخة تجريبية للعميل

آخر تحديث: 2026-10-01

النسخة الحالية تحتاج اختبار قبول على هاتف فعلي قبل إرسالها للعميل. العملاء والقضايا والتعيينات تعمل محلياً مع المزامنة؛ الجلسات والمراحل والمهل والملاحظات مشتركة على الخادم وتحتاج اتصالاً. المالية والمستندات ما زالت على الجهاز، فاستخدم بيانات تجريبية أثناء التحقق.

للتجربة المستقلة استخدم APK من EAS Internal Distribution؛ لا يعتمد تشغيله على استمرار خادم التطوير على حاسوبك. إعداد preview موجود، لكن عملية الدمج هذه لم تنتج APK أو رابط تنزيل جديداً. [توثيق Expo](https://docs.expo.dev/build/internal-distribution/).

## الإعداد (مرة واحدة)

```bash
npm i -g eas-cli
eas login
cd apps/mobile
eas init        # يكتب projectId في app.json؛ اعمل commit للتغيير
```

إعدادات Supabase للبناء في `apps/mobile/eas.json` (`build.base.env`)، لأن `.env` مستثنى من Git ولا يصل إلى خوادم EAS. المفتاح publishable وليس سراً؛ لا تضع أبداً مفتاح `service_role` في التطبيق.

## أندرويد: رابط APK

```bash
cd apps/mobile
eas build --profile preview --platform android
```

بعد نجاح البناء يعطيك EAS رابط التثبيت. اختبر الملف أولاً، ثم أرسل الرابط للعميل ليفتحه من هاتف Android ويثبّت APK. روابط التوزيع الداخلي متاحة افتراضياً لمن يملك الرابط، إلا إذا عطّلت الوصول غير المسجّل في إعدادات مشروع Expo. [توثيق Expo](https://docs.expo.dev/build/internal-distribution/).

## آيفون: TestFlight

يحتاج اشتراك Apple Developer.

```bash
eas build --profile production --platform ios
eas submit -p ios
```

ثم أضف بريد العميل كمختبر في TestFlight.

## بدون تثبيت: رابط ويب

```bash
cd apps/mobile
# جهز .env إن لم يكن موجوداً، ولا تستبدل إعداداتك الحالية
npx expo export --platform web --clear
eas deploy --prod
```

الجلسة المحفوظة تفتح البيانات المشتركة بعد تحديث الصفحة. المالية المحلية قد تتطلب فتح الخزنة الأصلية من «المزيد» بكلمة مرورها؛ لا يُحذف محتواها عند تغيير كلمة مرور الحساب.

## حساب العميل

إما أن ينشئ مالك المنصة مكتباً ومديره من `/platform`، أو يطلب العميل بنفسه من شاشة الدخول ← «اطلب مكتباً تجريبياً»، ثم يوافق مالك المنصة على الطلب من بطاقة «طلبات المكاتب التجريبية» في `/platform`. رقم الهاتف سوداني (`09xxxxxxxx`) ولا تُرسل رسائل SMS، فالرقم اسم مستخدم فقط. كلمة المرور 10 أحرف على الأقل.

تم تعطيل «Allow new users to sign up» وحفظ الإعداد بتاريخ 2026-10-01؛ إنشاء الحسابات يمر عبر manage-users. حماية كلمات المرور المسربة ما زالت غير مفعلة، وتعرض لوحة المشروع أنها متاحة على Pro فقط. لم يتم تغيير الاشتراك. [توثيق حماية كلمات المرور](https://supabase.com/docs/guides/auth/password-security).

اختبار القبول الكامل: طلب مكتب → رسالة انتظار → موافقة من واجهة مالك المنصة → دخول المدير → إنشاء عميل وقضية → مزامنة جهاز ثانٍ → اختبار وضع الطيران والرجوع للاتصال. بعد موافقة المالك نجح اختبار الطلب المكرر وعزل الحساب المعلق عبر API، والموافقة عبر دالة الخادم، ثم دخول المدير؛ وحُذفت جميع كيانات الاختبار المحددة وملف كلمة المرور. تبقى تجربة واجهة الموافقة والجهازين والهاتف الفعلي.
