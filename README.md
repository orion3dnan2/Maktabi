# مكتبي — Maktabi

تطبيق عربي لإدارة مكاتب المحاماة في السودان، مبني على Expo 57 وReact Native وTypeScript وSupabase.

**آخر تحديث تنفيذي: 2026-10-01.** مرجع المنتج الأعلى هو [الرؤية الأصلية](docs/MAKTABI_MASTER_VISION.md)، وحالة الإنجاز في [خارطة التنفيذ](docs/IMPLEMENTATION_ROADMAP.md). [تقرير الدمج والاختبارات](docs/verification/trial-integration-2026-10-01.md) يوضح حدود النسخة الحالية.

## الموجود الآن

| الجزء | الحالة الفعلية |
|---|---|
| الدخول والصلاحيات | دخول برقم سوداني وكلمة مرور؛ أدوار المكتب والموكل ومالك المنصة؛ حماية RLS وعضوية مكتب نشطة |
| صاحب المنصة | إنشاء مكتب ومديره، عرض المكاتب وتعليقها وتفعيلها، قبول ورفض طلبات المكاتب التجريبية |
| صاحب المكتب | داشبورد باسمه الحقيقي، العملاء والقضايا والتعيينات وفريق المكتب والجلسات والمهل والنشاط |
| العملاء والقضايا والأطراف والتعيينات | مخزن محلي مشفر، طابور مزامنة دائم، فصل المستخدم والمكتب، معالجة التعارضات وإعادة المحاولة؛ Supabase مصدر الحقيقة المشترك |
| الجلسات والإجراءات والمراحل والمهل والملاحظات | مشتركة على Supabase؛ تحتاج اتصالاً؛ مزامنتها للعمل دون اتصال لم تُنفذ بعد |
| المالية والمستندات وإعدادات المكتب | الوظائف الحالية محفوظة في خزنة المستخدم المشفرة على الجهاز؛ غير مشتركة بين الأجهزة |
| طلب مكتب تجريبي | نموذج الدخول → طلب معلق → موافقة مالك المنصة → صلاحيات المكتب؛ منع إساءة الاستخدام وسجل تدقيق |
| استيراد البيانات القديمة | اختيار ومعاينة من المدير، ربط ثابت للعملاء والقضايا، الاحتفاظ بالأصل المشفر وربط المالية المحلية بالقضية المستوردة |
| النشر | إعداد preview APK موجود؛ تصدير حزم Android/iOS/Web ناجح؛ لم يُبن APK في عملية الدمج هذه |

لا يزال ناقصاً: الاشتراكات والفوترة، تقارير المنصة الشاملة، المالية المشتركة، رفع المستندات ومزامنتها، الإشعارات الفعلية، المكتبة القانونية والذكاء الاصطناعي وواتساب. داشبورد مالك المنصة الحالي لوحة إدارة مكاتب وطلبات، وليس نظام تشغيل تجاري كاملاً للمنصة.

## حالة التحقق

- **205 اختبارات ناجحة:** 169 للموبايل و36 للـDomain.
- TypeScript وExpo lint ناجحان؛ صفر أخطاء وصفر تحذيرات lint.
- إعادة بناء قاعدة جديدة من **27 migration** نجحت على PostgreSQL 18 مع محاكاة مخططات Supabase للاختبار؛ الإضافة الأخيرة تسجل تنظيف حساب الاختبار المصرح به.
- اختبارات SQL السبعة للصلاحيات والعزل والعملاء والقضايا ومساراتها والمزامنة وطلبات المكاتب ناجحة.
- الإصلاح الإضافي `20261001095602_trial_integration_guards` مطبق؛ `manage-users` إصدار **8 ACTIVE**.
- التسجيل العام المباشر في Supabase معطّل. حماية كلمات المرور المسربة غير مفعلة؛ لوحة المشروع تعرض أنها تتطلب خطة Pro.
- بعد موافقة المالك، نجح طلب مكتب فعلي مكرر عبر API وعزل الحساب المعلق، ثم الموافقة عبر دالة الخادم والدخول بعضوية مدير نشطة. حُذف الحساب والمكتب وجلساتهما وبيانات الاختبار وملف كلمة المرور، وتأكدت الأعداد الصفرية ورفض الدخول بعد الحذف. واجهة موافقة مالك المنصة لم تدخل في هذا الاختبار.
- اختبارات الهاتف الحقيقي وSQLite/SecureStore ووضع الطيران على جهازين تبقى شروط قبول النسخة قبل التسليم.

## تشغيل المشروع على Windows

من PowerShell:

```powershell
cd "C:\Users\ORIONSer\Downloads\Maktabi\Maktabi"
pnpm install --frozen-lockfile
# مرة واحدة فقط إن لم يكن ملف البيئة موجوداً:
if (!(Test-Path apps/mobile/.env)) { Copy-Item apps/mobile/.env.example apps/mobile/.env }
pnpm --filter @maktabi/mobile start --clear
```

املأ عنوان Supabase والمفتاح publishable في `apps/mobile/.env`. لا تستخدم service_role في التطبيق. في CMD أمر النسخ هو `copy`؛ `Copy-Item` خاص بـPowerShell.

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

اختبار SQLite المحلي يستخدم Node 24. إعداد EAS للبناء يستخدم Node 22.23.3 ولا يشغّل اختبار node:sqlite.

## إرسال نسخة تجريبية

الخطوات في [دليل النسخة التجريبية](docs/trial-release.md). الملف `apps/mobile/eas.json` يحدد APK داخلياً؛ يلزم ربط المشروع بحساب Expo وبناء النسخة واختبارها قبل إرسال الرابط.
